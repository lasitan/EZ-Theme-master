# 每个端点负责内容

按前端页面说明：每个接口给哪一块 UI / 流程用、读哪些字段。路径均相对于 `{BASE}`（`/api/v1`）。

---

## 落地页 / 登录注册

| 端点 | 负责内容 |
|------|----------|
| `GET /guest/plan/fetch` | 落地页展示可售套餐名称与价格，吸引未登录用户 |
| `GET /guest/comm/config` | 登录/注册/找回密码：是否强制邀请、是否邮箱验证、是否验证码及 site key |
| `POST /passport/auth/login` | 邮箱密码登录，拿到 JWT 写入本地后进仪表盘 |
| `POST /passport/auth/register` | 注册账号；成功后通常再走登录 |
| `POST /passport/auth/forget` | 用邮箱验证码重置密码 |
| `POST /passport/comm/sendEmailVerify` | 给注册或找回密码发验证码；`isForgetPassword` 区分场景 |
| `GET /passport/auth/token2Login` | 邮件里的一次性登录 token 换会话 |
| `POST /passport/auth/loginWithMailLink` | 请求把登录链接发到邮箱 |
| `GET /passport/auth/google/login` | 浏览器跳转 Google OAuth，`redirect` 为登录后回到的前端路由 |

## 仪表盘

| 端点 | 负责内容 |
|------|----------|
| `GET /user/info` | 欢迎区邮箱、账户余额（分 → 元） |
| `GET /user/getSubscribe` | 当前套餐名、到期日/永久、剩余流量、重置日、订阅链接、是否允许提前周期 |
| `GET /user/getStat` | 顶部待办：`data[0]` 待支付订单、`data[1]` 待处理工单；为 0 则不显示对应入口 |
| `GET /user/notice/fetch` | 公告轮播；`tags` 含「弹窗」时首次进入弹窗 |
| `GET /user/comm/config` | 货币符号，用于余额展示 |
| `POST /user/order/save`（`period=reset_price`） | 「重置流量」下单，成功后带 `trade_no` 去支付页 |

仪表盘**不**用 `getStat` 的 `data[2]`（邀请人数）。余额卡片不可点进充值（已去掉 Xiao 钱包）。

## 商店 / 下单 / 支付 / 订单列表

| 端点 | 负责内容 |
|------|----------|
| `GET /user/plan/fetch` | 商店卡片：名称、说明、各周期价、库存、买断筛选 |
| `GET /user/plan/fetch?id=` | 订单确认页加载单个套餐与周期 |
| `GET /user/comm/config` | 商店/确认页货币符号 |
| `POST /user/coupon/check` | 校验优惠码；固定额或百分比折扣展示 |
| `POST /user/order/save` | 创建订单，`data` 为 `trade_no`，跳转支付页 |
| `GET /user/order/detail` | 支付页产品信息、金额明细、订单状态 |
| `GET /user/order/getPaymentMethod` | 支付方式列表（名称、图标、手续费） |
| `POST /user/order/checkout` | 发起支付：`type=0` 弹二维码，`type=1` 跳转支付链接 |
| `GET /user/order/check` | 支付后轮询：`0` 等待，`1` 成功去仪表盘，`2` 已取消 |
| `POST /user/order/cancel` | 取消未支付订单 |
| `POST /user/comm/getStripePublicKey` | Stripe 支付公钥（若启用该渠道） |
| `GET /user/order/fetch` | 订单列表：单号、周期、金额、状态；仅待支付可取消 |

`period` 决定确认页/列表显示的计费周期文案（月付、年付、重置流量等）。

## 工单

| 端点 | 负责内容 |
|------|----------|
| `GET /user/ticket/fetch` | 工单列表：标题、状态、优先级、更新时间 |
| `GET /user/ticket/fetch?id=` | 会话消息；`is_me` 区分用户/管理员；开启状态才轮询 |
| `POST /user/ticket/save` | 新建工单；正文可能附带套餐、IP 等信息 |
| `POST /user/ticket/reply` | 发送回复 |
| `POST /user/ticket/close` | 关闭工单，之后不能再回 |

桌面与移动工单页共用这组接口。

## 请求层公共行为（所有 `{BASE}` 接口）

`src/api/request.js`：

- 所有 POST 的 JSON 会转成 `application/x-www-form-urlencoded`
- 自动附加 `Authorization`
- 若 body 的 `message` 为「未登录或登陆已过期」，清登录态并跳转登录页

因此对接后端时：登录接口必须返回可用 JWT；业务错误用 HTTP 状态或 `message` 即可，前端会展示 `error.response.message`。
